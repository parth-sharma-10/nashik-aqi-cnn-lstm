# Nashik air-quality forecasting: KNN imputation + CNN-LSTM

This project forecasts hourly concentrations of seven pollutants (PM2.5, PM10, NO2, SO2, CO, O3, NH3) at four Nashik monitoring stations. Missing inputs are filled with KNN imputation, and each station gets its own CNN-LSTM that predicts the next hour from the previous 24.

The pipeline runs in two separate modes. Each writes to its own folder.

| Mode (`NASHIK_MODE`) | Trained on | Forecast horizon | Ground truth in the files |
|---|---|---|---|
| `backtest_2025` | data up to 2024-12-31 | every hour of 2025 | all four stations, all 12 months |
| `forecast_2026` (default) | data up to 2025-12-31 | every hour of 2026 | Jan-Jun and Aug 2026 at MIDC Ambad, Gangapur Road and Hirwadi; none at Pandav Nagari (its file ends 2025-12-31) |

Each mode produces two kinds of prediction, reported separately:

- **Recursive forecast.** Every hour of the horizon is forecast from the last 24 hours before the origin, and each prediction is fed back as input. No measurement after the origin is used. Every hour is exported, measured or not.
- **Rolling one-step evaluation.** The frozen model predicts each measured hour from the measured previous 24 hours, which is the operational next-hour use. Measurements after the origin are inputs here, never training data.

**Read this before using the 2026 numbers.** As a year-ahead forecast, the recursive CNN-LSTM is worse than the hour-of-day climatology for every pollutant, in both the 2025 backtest and the measured part of 2026. At Gangapur Road and Pandav Nagari it drifts to implausible levels in several months: for example, Gangapur Road's December 2026 PM2.5 mean is 325 µg/m³ against a climatology of 56. The `climatology_pred` column of the same file is the better year-ahead estimate. The network's real but modest value is one hour ahead, with fresh measurements, where it beats persistence. Details are in the report.

AQI (CPCB National AQI, `aqi_cpcb.py`) is derived from the predicted concentrations, and from the measurements on days where a valid AQI can be computed. Neither one is an official AQI bulletin.

## Files

| Path | What it is |
|---|---|
| `nashik_aq_pipeline.py` | The pipeline. The notebook is generated from it. |
| `aqi_cpcb.py` | CPCB AQI sub-indices and daily AQI |
| `Nashik_AQ_CNN_LSTM.ipynb` | Colab notebook, generated by `scripts/make_notebook.py` (not executed) |
| `scripts/verify_outputs.py <mode>` | Independent checks. It replays the forecast from raw data truncated at the cutoff (leakage), rebuilds one-step windows from the raw files (alignment), checks horizon and ground-truth labelling, and recomputes every metric. |
| `scripts/build_report.py` | Builds `outputs/Nashik_AQ_Forecast_2026_Report.docx` from both modes' outputs. Every number in it is read from the result files. |
| `tests/test_pipeline.py` | `unittest` suite: AQI rules, horizon length, schema, alignment, missing ground truth; also runs the verifier |

Per mode, under `outputs/<mode>/`:

| Path | What it is |
|---|---|
| `predictions/recursive_forecast.csv` | One row per station × hour × pollutant for all 8,760 horizon hours. Contains the forecast, the baselines, `actual` (empty if not measured) and `ground_truth` (`observed` / `missing_value` / `no_row_in_file`). |
| `predictions/rolling_one_step.csv` | One row per measured station × hour × pollutant with a valid 24-hour input window |
| `metrics/recursive_*.csv`, `metrics/one_step_*.csv` | MSE / RMSE / MAE / R² per station and pollutant, plus a pooled per-pollutant summary. Includes `n_valid`, evaluation period, coverage, R² reliability flag and quality flag. |
| `metrics/daily_aqi.csv`, `metrics/aqi_summary.csv` | Predicted and measured daily CPCB AQI and category |
| `metrics/model_selection_validation.csv` | Validation losses used to choose the target design |
| `tables/horizon_coverage.csv` | Rows, measured hours and missing months per station in the horizon |
| `run_metadata.json` | Cutoff, horizon, features, target order, selected designs, model paths, coverage, versions, git commit |
| `figures/*.png` | Forecast vs measured (grey = no measurement), scatter, residuals, RMSE by month, daily AQI |
| `models/` | `.keras` models (both designs) and per-station scaler + imputer (`.joblib`) |

The files directly under `outputs/` (`metrics/`, `predictions/`, `figures/`, `Nashik_AQ_CNN_LSTM_Report.*`) are from the earlier one-step study, and are kept unchanged.

## Run locally

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
# put the four CSVs in data/
NASHIK_MODE=backtest_2025 .venv/bin/python nashik_aq_pipeline.py
NASHIK_MODE=forecast_2026 .venv/bin/python nashik_aq_pipeline.py   # also builds the DOCX
.venv/bin/python scripts/verify_outputs.py backtest_2025
.venv/bin/python scripts/verify_outputs.py forecast_2026
.venv/bin/python -m unittest discover tests -v
soffice --headless --convert-to pdf --outdir outputs outputs/Nashik_AQ_Forecast_2026_Report.docx
```

Each mode takes 4-6 minutes on a laptop CPU, mostly training. `NASHIK_REUSE_MODELS=1` reloads that mode's saved checkpoints instead of retraining (about 2 minutes). `NASHIK_EPOCHS=1` is for smoke runs only. The reported results came from Python 3.12, TensorFlow 2.19.1, pandas 3.0, scikit-learn 1.9 and NumPy 2 on CPU, with seed 42.

## Run in Google Colab

1. If the script changed, regenerate the notebook: `python scripts/make_notebook.py nashik_aq_pipeline.py Nashik_AQ_CNN_LSTM.ipynb`.
2. Open `Nashik_AQ_CNN_LSTM.ipynb` in Colab. A CPU runtime is enough.
3. The notebook runs the `forecast_2026` mode. For the backtest, first run `import os; os.environ["NASHIK_MODE"] = "backtest_2025"` in a new cell.
4. Choose Runtime → Run all. When the upload cell prompts, select the four station CSVs (or the Nashik zip). Stations are matched by file name (`midcambad`, `gangapur`, `pandav`, `hirwadi`).

On a GPU runtime, the numbers can differ slightly because cuDNN LSTM kernels are not bit-identical to the CPU kernels.

## Design in one paragraph

Each station is cleaned with documented rules: the ≥999 PM analyser ceiling is set to missing, as is any value repeated for 12 or more hours (a stuck sensor). Missing hours are never interpolated. Within each mode, the validation set is the six months before the forecast origin and training is everything earlier. The scaler and KNN imputer (k=5) are fitted on training rows only. Inputs are 24 hours of 7 pollutants plus 6 calendar encodings; windows never span a gap. The model is Conv1D×2 → MaxPool → LSTM(64) → Dropout → Dense → 7 outputs, trained with masked MSE, so missing targets are never imputed into the loss. Two target designs are trained: predicting the level, and predicting the change from the last observation. Two selections are made on validation data: the recursive forecast uses the design with the lower recursive validation error, and the one-step evaluation uses the design with the lower one-step validation loss. Predictions are clipped at zero. Metrics are computed in original units on measured hours only, against climatology, same-hour-last-year and persistence on the same rows.
